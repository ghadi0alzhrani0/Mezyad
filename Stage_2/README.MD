# Portfolio Project - Project Planning and Project Charter (Stage 2)

## Objectives & Purpose
The purpose of Stage 2 is to introduce students to the basics of project management by creating a simple yet structured project document known as the Project Charter. This stage defines the project's purpose, SMART objectives, stakeholder roles, scope boundaries, potential risks with mitigation strategies, and a high-level timeline mapping out the lifecycle of the 12-week development process.

---

## Importance of Stage 2
The Project Charter serves as the foundational reference point for all subsequent work. It establishes a shared, aligned understanding of the project among all cross-functional team members and external evaluators, providing a reliable baseline for decision-making throughout the project lifecycle.

---

## Tasks to Complete Stage 2

### 0. Define Project Objectives
* Articulate the core purpose of the project and why it matters in addressing real-world market gaps.
* Formulate 2 to 3 specific **SMART objectives** (Specific, Measurable, Achievable, Relevant, Time-bound) that the MVP will achieve, focusing on real-time synchronization, workflow data validation, and frontend optimization.

### 1. Identify Stakeholders and Team Roles
* Document all project stakeholders, separating them into Internal (development team) and External (evaluating SWEs and simulated end-users).
* Define team roles under the Cross-Functional Agile Team model where all members operate as Full-Stack Developers, while distributing primary coordination domains (Project Manager/DevOps, Database Lead, Backend/Real-Time Lead, Frontend UI/UX Lead).

### 2. Define Scope
* Outline absolute scope boundaries to prevent "scope creep" and protect Quality Assurance (QA) capacity.
* Explicitly list **In-Scope** deliverables (Authentication/RBAC, Simulated Escrow Wallet, Real-Time Bidding Room, Anti-Sniper Logic, Admin Approval Workflow, and HTML5/CSS3/Vanilla JS frontend).
* Explicitly list **Out-of-Scope** items (Heavy frontend frameworks like React/Next.js, live banking APIs, AI/ML, Blockchain, and mobile apps).

### 3. Identify Risks & Mitigation Strategies
* Proactively brainstorm potential project risks across technology, timelines, and team dynamics.
* Formulate concrete technical and managerial mitigation plans for each risk (e.g., modular Vanilla JS patterns, PostgreSQL row-level locking, unified JSONB metadata schemas, daily on-site pair programming, and Socket.io room isolation).

### 4. Develop a High-Level Plan
* Map out the major phases and milestones across the 12-week lifecycle, covering Stage 1 (Idea Development), Stage 2 (Project Charter), Stage 3 (Technical Documentation), Stage 4 (MVP Development / Sprints A, B, and C), and Stage 5 (Project Closure & QA).
